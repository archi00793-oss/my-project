# Универсальные компоненты движка

Все примеры рассчитаны на `VIDEO` из `src/config/video.ts` (1080×1920, 30 fps).
`sec()` переводит секунды в кадры проекта. Внутри другой композиции можно брать `fps`
через `useVideoConfig()`. Все интервалы: начало включительно, конец не включительно.
Компоненты не импортируют `Hero` и подходят для любого содержимого сцены.

## Camera: масштаб, сдвиг и тряска

```tsx
import { Camera } from "../components/Camera";
import { sec } from "../config/video";

<Camera
  transformOrigin="50% 40%"
  keyframes={[
    { frame: 0, zoom: 1.05 },
    { frame: sec(2), zoom: 1.2, x: -30, y: 20 },
    { frame: sec(4), zoom: 1.05, x: 0, y: 0 },
  ]}
  shakes={[{ from: sec(1), durationInFrames: sec(0.4), strength: 14, seed: "удар" }]}
>
  <MyScene />
</Camera>
```

`zoom` — множитель масштаба; положительные `x/y` двигают содержимое вправо/вниз,
единицы — пиксели. Ключевые кадры должны строго возрастать. Незаданные значения
наследуются из предыдущего ключа; начальные — `zoom=1, x=0, y=0`. Один ключ задаёт
постоянную камеру. Между ключами действует плавное ускорение/замедление, за пределами
диапазона удерживается крайнее положение.

`shakes` можно накладывать друг на друга. `strength` — пиксели (по умолчанию 12),
`rotation` — градусы (0.6), `frequency` — радианы на кадр (1.8), `seed` — строка
для повторяемого рисунка. Сила плавно уходит в ноль на краях окна. Длительность —
не менее двух кадров. Для тряски и сдвигов оставляйте запас масштаба, чтобы не
показывать край сцены. Сам контейнер обрезает вышедшее за кадр содержимое.

Кадр камеры локален относительно родительской `Sequence`. Субтитры, счётчик и другие
неподвижные элементы интерфейса размещайте рядом с `Camera`, за её пределами.

## Transitions: вспышка, быстрый наезд, шторка

```tsx
import { Transitions } from "../components/Transitions";
import { COLORS, sec } from "../config/video";

<Transitions scenes={[
  { id: "intro", durationInFrames: sec(3), content: <Intro /> },
  {
    id: "next", durationInFrames: sec(3), content: <NextScene />,
    transition: { type: "flash", durationInFrames: sec(0.4) },
  },
  {
    id: "closeup", durationInFrames: sec(3), content: <Closeup />,
    transition: { type: "zoom", durationInFrames: sec(0.4), zoom: 1.65 },
  },
  {
    id: "final", durationInFrames: sec(3), content: <FinalScene />,
    transition: {
      type: "wipe", durationInFrames: sec(0.6),
      direction: "right", color: COLORS.captionAccent,
    },
  },
]} />
```

`transition` относится к входу в указанную сцену. У первой сцены его нет.
`id` должен быть уникальным; `name` необязателен и задаёт подпись в Studio.
Сцены размещаются через `Series.Sequence`, цветовые накладки — через `Sequence`.
Эффект центрируется на склейке: первая часть до неё, вторая после. Общая длительность
равна **сумме длительностей сцен**; вычитать переходы не нужно. Локальный кадр каждой
сцены начинается с нуля, а внешние субтитры и SFX продолжают общую шкалу времени.

Минимальная длительность перехода — четыре кадра. Он должен помещаться в обе
соседние сцены и не пересекаться с другим переходом. Неверные параметры дают ошибку.
`flash` по умолчанию белый, `wipe` жёлтый; другой цвет берите из `COLORS`.
Направления шторки: `left`, `right`, `up`, `down`. `zoom` масштабирует содержимое
обеих соседних сцен около склейки, его множитель должен быть не меньше 1.

## Captions и SRT

Прежние массивы `Caption` и прежний импорт типа работают:

```tsx
import { Captions } from "../components/Captions";
import type { Caption } from "../components/Captions";

const captions: Caption[] = [
  { text: "До цели 30 дней", from: 0, to: sec(2), accent: ["30 дней"] },
];

<Captions captions={captions} />                       // реплика целиком
<Captions captions={captions} mode="word-by-word" />   // слова появляются по одному
```

В новом режиме фраза постепенно накапливается, текущее слово подсвечивается.
Место следующих слов зарезервировано, поэтому строки не прыгают. Неразрывный пробел
сохраняет сочетание одним блоком. `top` и `fontSize` работают в обоих режимах.

Для файла `public/audio/ep01.srt`:

```tsx
import { Captions } from "../components/Captions";
import { useSrtCaptions } from "../components/useSrtCaptions";

export const Episode = () => {
  const captions = useSrtCaptions("ep01.srt");
  if (captions === null) return null;
  return <Captions captions={captions} mode="word-by-word" />;
};
```

Хук берёт fps композиции и задерживает рендер до загрузки; отсутствие файла или
неверный SRT останавливает рендер с сообщением. При смене файла/размонтировании
запрос отменяется. Допустим также путь `audio/ep01.srt`.

Для собственного загрузчика доступны:

```ts
import { loadCaptionsFromSrt, parseSrtCaptions } from "../animation/captions";

const captions = await loadCaptionsFromSrt("ep01.srt", VIDEO.fps);
const fromText = parseSrtCaptions(srtText, VIDEO.fps);
```

`parseSrtCaptions` использует строгий парсер `@remotion/captions`, адаптируя его
времена в миллисекундах к существующему типу `{ text, from, to, accent? }`.
Поддерживаются BOM, CRLF и многострочные реплики. Границы округляются до кадров;
очень короткая реплика занимает минимум один кадр. fps должен быть положительным.
Если вызываете асинхронную функцию из своего компонента, самостоятельно ожидайте
данные через `useDelayRender()`; в `useSrtCaptions` это уже сделано.

Обычный SRT не содержит разметки отдельных слов: время появления распределяется
равномерно внутри реплики, точная синхронизация с произнесением не обещается.
Для точных границ можно разбить SRT на более короткие реплики. Внутри `Sequence`
времена файла также должны относиться к локальному началу этой сцены.

## Sfx: звуковой эффект на нужном кадре

```tsx
import { Sfx } from "../components/Sfx";

<Sfx
  src="whoosh.wav"
  from={sec(2)}
  durationInFrames={sec(0.5)}
  trimBefore={0}
  volume={0.5}
  fadeInFrames={2}
  fadeOutFrames={3}
/>
```

Файл здесь: `public/sfx/whoosh.wav`. `src` — относительный путь внутри `public/sfx/`;
допустим и префикс `sfx/`. Используется `Audio` из `@remotion/media`.
`from` — локальный кадр начала, `trimBefore` — сколько кадров пропустить в файле.
Без `durationInFrames` звук играет до естественного конца файла. С явной длительностью
он обрезается; короткий файл не продлевается и не зацикливается.
Громкость — 0..1, затухания — неотрицательные целые кадры.
`fadeOutFrames` требует `durationInFrames`. Несколько `Sfx` могут играть одновременно.

В репозитории есть собственные короткие синтетические звуки `shake.wav`, `flash.wav`,
`zoom.wav`, `wipe.wav` для проверки таймингов. Их можно заменить готовыми эффектами.
Повторная генерация: `node scripts/generate-demo-sfx.mjs`.

## Проверка на Ep00-Test

Длительность — 10 секунд (300 кадров):

| Время | Что проверяется |
| --- | --- |
| 0–2.5 с | Камера: наезд/отъезд, сдвиг, тряска в 1.6 с; прежние субтитры |
| 2.5 с | Вспышка и соответствующий SFX |
| 2.5–5 с | Дневная сцена, слова постепенно появляются из SRT |
| 5 с | Быстрый наезд, звук начинается в 4.8 с |
| 7.5 с | Шторка, звук начинается в 7.2 с |
| 7.5–10 с | Финальная сцена, продолжаются пословные субтитры |

Верхние плашки показывают название демонстрации, режим субтитров и активный звук.
Речь и музыка не добавлялись: слышны только тестовые эффекты.

```powershell
npm run typecheck
npm run test:engine
npx remotion still src/index.ts Ep00-Test out/check.png --frame=60
npx remotion render src/index.ts Ep00-Test out/ep00-test.mp4
```

Для `test:engine` нужен Node.js 22.18+ (встроенное чтение TypeScript).
Тесты проверяют границы/повторяемость камеры, окна переходов, SRT, разбиение слов,
ошибки загрузки, огибающую SFX и WAV-файлы. Проверяйте картинку и звук отдельно:
один контрольный PNG не показывает движение и не подтверждает звуковую дорожку.
